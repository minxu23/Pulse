# Pulse 交互整改验收

日期：2026-11-08。

## 页面结构与字号

- 页面自绘内容统一为 22 pt 标题、16 pt 正文两档，跟随系统动态字号放大；图表刻度也使用正文档位。系统导航、键盘和原生控件保留系统行为。
- 本周复盘纵向排列「本周变化」「改进方向」「下周计划」，保留每日、本周、长期的范围切换。
- 改善期优先显示主靶点、训练完成和日均步数。记录模式隐藏训练完成率，不生成训练要求。
- Personal Health Agent 在「本周变化」主动提供解读，结合当前健康档案、主靶点与测量波动、本人的行为关联和本周反馈；「改进方向」优先展开一项带依据、可采纳的个性化建议，其余信息按需展开。模型按既有回答方式生成，模型不可用时明确标注本机分析。
- 过往周次的分析重新计算截至该周的观察与关联；记录模式不设训练要求。相同事实复用已生成解读，用户可重新生成或继续讨论。反馈中的姓名与联系方式在云端生成前进行本机去标识处理。
- 复盘底部保留 Health Agent 文字、语音入口；从过往周次进入时携带日期范围，指标数据截止到对应周次。

## 审核问题对应整改

| 原问题 | 当前行为 |
| --- | --- |
| 预设资料被当成已填写 | 新档案不预填出生年份、身高和体重；未知资料不参与同龄排名和 BMI 计算。Apple 健康填充须预览并确认，没有读取到的项目保留原输入。 |
| 安全问题可跳过直接开方案 | 开始改善前须有年龄信息并逐项回答七项安全问题；未回答与回答「否」分开。有需要先就医的情况须确认医生已允许。 |
| 血压靶点与统计口径不清 | 主靶点名称为「血压」，测量方式另行说明。有高血压或基线血压偏高时使用血压；没有血压问题时使用静息心率。当前数值同时显示收缩压与舒张压，本轮按收缩压目标评价。 |
| 有无血压设备分支不清 | 有设备时使用近七天平均；无设备时使用最近一次门诊或药店读数。明确选择没有血压计时，已有少量读数不会覆盖该选择。 |
| 图表与主数值含义不同 | 说明每日收缩压均值与主数值统计口径，显示读数数量、最近记录和本轮开始分界；开始前不展示本轮训练完成率。 |
| 新旧阶段并存 | 欢迎页支持五种使用方向；记录模式不强制改善。选择改善时，建档完成后进入基线流程，统一为基线、四周改善、总结三个阶段。 |
| 开始前缺少计划承诺 | 确认页显示基线、数值目标、起止日期、实际生成的首周训练天数与总分钟、步数和测量要求；说明正式开始前的过渡安排。 |
| 承诺可换方案却无入口 | 我的方案提供更换入口，我的提供方案与历史报告；更换时开始新一轮，保留历史和当前周的过渡安排。使用方向经确认后生效。 |
| 空首页缺少下一步 | 首屏提供连接状态、同步中、最近同步和检查读取结果入口；缺失数据与实际为零分开。 |
| 报告主要行动靠后 | 首屏给推荐方案，底部保留查看推荐方案入口；习惯与参考详情可展开。 |
| 示例入口与退出混在正常使用中 | 正常模式不提供示例用户选择。在关于页连续点击版本七次后进入测试模式；测试模式持续显示标记与退出入口。个人、示例档案和对话分别保存。 |
| 权限时机与可访问性细节 | 天气在主动开启后才请求定位；标签提高文字对比并提供选中状态，排名条和周进度合并辅助功能描述，避免逐项重复朗读。 |
| 健康状况未知与没有疾病混淆 | 提供「没有上述情况」与「暂不填写」，未确认时明确显示状态；生活习惯问题保留未填写选项。 |

## 验证

- 恢复智能复盘后的完整本地回归：320 项通过；跳过 CloudLiveTests，没有进行云端模型调用。
- 收尾的 28 项复盘与身份过滤相关测试通过，包含新补的确定性因果措辞检查和反馈去标识检查。模型成功、缓存、重写及失败回退使用替身生成器测试。
- Release 模拟器构建通过。
- 独立模拟器在强制仅本机模式下，实际运行端侧 Apple 智能生成路径并显示解读来源；本次有两处文字经过校验后使用本机规则原文，未调用云端模型。
- 独立 iPhone 模拟器抽查：欢迎页、空资料、健康状况确认、记录模式空首页、改善第二周复盘、过往周次进入 Health Agent、血压详情。较大辅助字号抽查确认指标行改为纵向排列。
- 自动化验证覆盖：档案持久化切换、内存档案切换、个人与示例对话隔离、未完成安全筛查不能开始、换方案保留历史、确认页训练投入与实际计划一致、无数据与零值区别、主靶点呈现顺序及血压设备分支。
