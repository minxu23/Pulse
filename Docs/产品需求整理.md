# Pulse 产品需求

本文只列当前生效的产品功能和体验要求。

## 一、产品定位

- 产品目标：通过可持续的运动、睡眠、饮食和恢复管理，促进适合个人情况的静息心率改善，同时提升日常精力与运动能力。
- 管理过程：了解个人基础 → 改善日常行为 → 按身体状态调整 → 验证长期效果。
- 以降低静息心率为长期管理目标，串联运动、睡眠、饮食、身体指标和恢复。
- 一句话定位：把手表里的各项数据，变成今天该怎么做。
- 核心能力：设定目标，按目标定计划，按每天的身体状态调计划，验证不良生活习惯与身体体征的关系。
- 除心率、睡眠和活动外，把可穿戴设备能测到的血压、血糖、血氧等身体参数放在一起看。
- 智能手表、CGM 和手动记录都是获得信息的途径，按人群和场景选择。
- 身体准备度回答「今天如何安排」，身体活力度回答「今天实际活动了多少」，两者共同支持计划调整。
- 当天回顾帮助安排恢复，长期复盘帮助判断方向是否合适，两者要衔接。
- 进展要综合衡量：除静息心率趋势外，还看活动持续性、睡眠规律、主观精力和运动能力，避免用户因短期心率没降而否定已有改善。
- 睡眠呼吸健康是核心需求，设备信号和自述线索要和专业诊断区分。

## 二、十项核心需求

1. **建立个人健康基础与管理目标**：明确静息心率基础、运动基础、健康状况、用药背景和生活限制。运动目标、目标日期和可投入时间纳入整体管理。
2. **持续了解静息心率变化**：在可比较的条件下看长期趋势，分清单次波动和持续变化，结合疾病、压力、饮酒、训练和用药解释变化。数据不足或条件改变时说明判断的局限。
3. **了解晨起状态与身体准备度**：综合昨夜睡眠、夜间指标、近期负荷和醒后感受，给出 Body Readiness 判断及依据。
4. **获得可持续的运动与日常活动安排**：按目标、基础、健康状况和可用时间给出能融入生活的计划，兼顾规律运动、日常活动和恢复。
5. **根据实际情况调整当天安排**：结合准备度、已完成活动、疲劳、酸痛和身体反馈调整运动量、强度或恢复，并说明原因。忙碌、漏练或状态变化时也能继续。
6. **改善睡眠并跟进睡眠呼吸问题**：管理作息，记录打鼾、憋醒、被观察到呼吸暂停等线索。需要时获得专业评估支持，已确诊用户能跟进治疗和照护。
7. **管理影响恢复的日常行为**：管理饮食、饮水、运动补给、压力、咖啡因和酒精，睡前明确当晚要关注的恢复事项。
8. **关注相关身体指标与异常事件**：结合心率、血压、血糖和夜间数据，保留测量、活动、饮食和用药背景。需要核实或专业处理的异常要独立跟进。
9. **回顾行为与健康变化，调整长期策略**：关联回顾活动、睡眠、饮食、恢复和静息心率，了解哪些习惯能坚持、下一阶段调整什么。区分观察到的关联和已确认的原因。
10. **低负担地持续记录并掌握自己的信息**：能记录、补充、修改和查看历史，减少重复记录。没有设备也能完成基本记录和回顾，健康信息的使用和对外提供由用户控制。

## 三、今日

### 页面

- 首页尽可能简单，合并同类项，突出重点。
- 入口用清晰的图形入口，不用文字列表。
- 首屏内容不杂乱，不用底色干扰重点信息。
- 卡片支持拖拽和增删。
- 相邻卡片大小一致。
- 开通专项运动、血压、血糖功能后，首页出现相应卡片。
- 血糖和血压用小卡片，和「运动」一样大。
- 运动卡片显示当天天气提醒。
- 乳酸只放在专业运动场景，不放首页。

### 全天各阶段

- 围绕从起床到入睡的完整过程，明确各阶段要关注的信息和行动。
- 晨起健康评估在早餐前完成，结合昨夜睡眠、夜间指标和醒后感受，特别关注夜间血压和血糖波动。
- 运动记录包含类型、时间、时长、距离、强度和感受，结合步数和日常活动反映实际活动水平。
- 管理饮食、饮水和补给。
- 睡前记录疲劳、酸痛、压力、咖啡因摄入和睡眠安排。
- 全天回顾汇总晨起状态、日间运动、身体指标和睡前感受，帮助安排恢复。

### 作息与时间

- 凌晨 5 点前算前一天，晨起评估、本周复盘和 Health Agent 都按这条规则判断。
- 提供「我已经起床了」入口：凌晨 3 点到 5 点显示，确认后提前开始新的一天，5 分钟内可撤销。
- 提供倒班设置，支持夜班作息。

## 四、趋势

- 标签页叫「趋势」，其中的指标页叫「关键指标」。
- 【血糖】栏显示基于 CGM 的连续血糖曲线，点击进入【血糖管理】。
- 血糖曲线不加灰色背景。
- 心脏相关曲线用 Apple 健康标准的红色。
- 趋势范围最长可选 1 年。
- 在趋势卡片中预测血压和血糖未来一段时间的走向。
- 血压和血糖做未来 1 小时的预测。
- 出现异常值时，提醒用户回忆可能的原因并备注，或与 Agent 对话分析。

## 五、计划

- 记录运动目标、目标日期、运动基础和可投入时间，制订可执行的个性化计划。
- 计划中的习惯管理栏目叫「恢复」。
- 能根据本周复盘刷新接下来一周的运动计划。
- 能根据天气预报调整计划。
- 计划调整后，重新检查改动那几天的天气。

## 六、复盘

### 结构与内容

- 复盘分每日回顾、本周复盘和长期复盘。
- Health Agent 给出综合评价和后续建议，用户可以用语音或文字继续追问。
- 页面服务 AI-Native 的交互方式。
- 复盘卡片由大模型生成。
- 复盘根据用户的优先事项自动优化。
- 底部的 Health Agent 入口什么都可以问，不限于本周数据。

### 本周与长期

- 减少视觉干扰，对用户有价值的复盘信息多一些、清晰一些。
- 【移出周六】【暂不】【开始验证】这类按钮尺寸要小。
- 总结的语气有人味，不像数字罗列。
- 建议条目的说明口语化。
- 【下周计划】【一起复盘】【每一天】卡片设计清爽美观。
- 本周复盘的标题先说排第一的优先事项。
- 长期复盘的「开始 2 周验证」只保留一个入口。

### 所处阶段

- 设计清楚易读。
- 已完成的阶段压缩显示。
- 按管理目标设置阶段：一张卡切换目标，由记录自动判断，使用现有 5 个目标。
- 已达成的阶段保留，不倒退。
- 下一步只写在【长期总结】里。

### 每日回顾

- 用日历展示每天的情况，可以点进任意一天。
- 每天的状态用顺利、平稳、有起伏、需留意来描述。
- 评价参考本人平时的水平。
- 长期超标的人不能因为「平时就这样」被放过。
- 血压按个人目标判断，措辞写清是哪个数值超标。

## 七、Health Agent

### 回答要求

- 非紧急问题由大模型结合身体数据写成回答，结论由规则根据用户记录和当前时间决定，模型不能改。
- 本机模型回答时，计划修改、症状、周总结和建议清单直接用规则原文。
- 紧急情况用固定提示，始终在本机回答。
- 回答要考虑当前时间，深夜和凌晨的回答要合理。比如凌晨还没睡时问明天能否做大力量训练，不能答「适合」。
- 回答时参考天气预报。
- 先回答用户问的问题，再给依据，不教条化，建议要具体。
- 计划没有采纳时，不能说计划「已改」。
- 记录没有确认时，不能说「已经帮你记了」。
- 结尾不放泛泛的建议。
- 不向用户显示提示词标签。
- 计划调整的回答写清每天改前和改后，不能写反。
- 回答下面的联想问题要和回答相关。
- 追问接着上一个话题回答，比如「那该注意什么」。
- 日常常见问题都能回答且不答偏，包括胸口闷等急症、腹透感染迹象和透析日运动。
- 能回答「X 对 Y 有影响吗」和不同比赛目标的问法。
- 能回答跑量够不够、夜班后何时运动、血糖早上高的原因、最近睡够了吗、今天动多久能达标。
- 云端模型不自己推算日程和达标情况，不显示英文强度词。
- 用户给 Agent 起名后，Agent 用「我」自称，不用第三人称。

### 对话中能做的事

- 支持语音和文字对话。
- 根据对话，结合本地数据和云端大模型调整训练计划。
- 针对训练需求，调用云端大模型指导穿戴设备和 CGM 的使用。
- 在复杂场景下用 Generative UI 生成交互界面。
- 支持撤回。
- 用户可以给 Health Agent 取名字。
- 能在对话中记录血压、血糖、体重、化验、饮水、症状、饮食和运动，并设置提醒。
- 从对话记的饭估算碳水，运动卡片可以修改。
- 撤销对话里的记录时，由它产生的异常提醒一起撤销。
- 过期的计划卡片不能再采纳。
- 重新打开 App 后对话还在。

### 回答展示

- 用一套回复模板：条理清晰，图文并茂，重点突出。
- 中文行距宽松，不拥挤。
- 开场建议问题 4 个。

### 回答方式与云端模型

- 在【我的】里设置回答方式，可选仅本机、端云结合和全部云端。
- 端云结合：问题里的个人信息打码后上传云端，回复回来后在本地拼成完整回答。
- 只对【直接能认出人的】信息打码，【组合起来可能认出人的】信息和【健康数据】不打码。
- 大模型服务提供 OpenRouter 入口，包括 Anthropic。
- 粘贴 API Key 后能顺利测试连接。

## 八、慢性病与专业支持

### 专业模块

- **专项运动**：针对全马等目标，提供训练评估、计划、补给指导和持续复盘，乳酸数据在适当条件下参与评估。
- **心血管健康**：按专业照护要求，协调关键指标、身体感受、活动、饮食、用药背景和随访。
- **血糖管理**：按照护计划关联管理血糖、饮食、运动、补给、用药背景和异常事件，适用时使用 CGM。
- 利用手表的运动与恢复数据和 CGM 数据，辅助训练计划、调整和补给管理。
- 基于用户的血糖监测数据，识别血糖代谢风险、评估胰岛素抵抗、预测餐后血糖。先做规则版血糖代谢画像，后续接入 GlucoFM。

### 慢性肾病与透析

- 肾病患者能用这个 App 管理日常。
- 疾病列表包含慢性肾病。
- 提供限水模式，喝水目标是上限。
- 体重快速上升时提醒。
- 记录化验结果，可以选单位，并提醒复查。
- 记录饮食，按份记录蛋白质、钾和磷。
- 记录水肿、尿量和泡沫尿。
- 提醒布洛芬这类可能伤肾的止痛药。
- 支持透析日和两次透析之间的体重增长。
- 支持腹膜透析。

### 其他慢性病

- 用户在聊天中提到自己是某种 App 没有原生支持的慢性病患者时，比如低血钾症，能根据检索到的信息自动调整。

## 九、提醒与通知

- 到期提醒发系统通知。
- 体重上涨和水肿加重这类异常，App 没打开时也能提醒。
- 支持重复提醒，比如每天晚上 9 点吃药。
- 支持隔天、每几天和透析后这类重复方式。
- 手动添加提醒时的重复选项和对话里一致，可以设时间。
- 「每周三次」和「每周三」要区分，「每周一次」和「每周一」要区分。
- 手机日历不是公历时，提醒也要按时响。

## 十、数据与隐私

- 记录持续保存，能补充、修改和查看历史。
- 用户控制健康信息的使用和对外提供。
- 导出的 CSV 跟随所选内容。
- 「删除所有数据」清除记录、设置和云端密钥。

## 十一、界面与视觉规范

### 配色

- 配色清爽，不杂乱。
- 二级页面减少不必要的颜色干扰，不影响识别。
- 导航栏用苹果标准蓝色，其他配色参考 Apple 健康 App，符合 UX 规范。

### 字体与排版

- 颜色、字体和字号符合苹果 UI 设计规范。
- 字号不能太小，说明文字要易读。
- 不同界面的中文字体一致。
- 辅助功能大字号下排版不能坏。
- 安全步骤用正文，不用灰色小字。
- 页面标题样式统一。
- 「我的 › 提醒」每个开关各有一行说明。

### 布局

- 所有页面美观，符合 UX 设计规范。
- 统一字号、圆角和间距，同级面板圆角一致。
- 两侧留白一致。
- 图标略小于文字，图文间距一致。
- 每行放得下文字和上下留白。
- 点击区域足够大。
- 组间距比组内更松，间距遵循统一规则。
- iPad 上内容有最大宽度。

### 图标

- 在原来的爱心图标基础上优化，设计精致。

## 十二、演示与介绍

- 目录下提供开箱即用的演示，不用打开 Claude Code。
- 提供健康情况一般、遵从性不太好的示例用户。
- 提供记录时间更长的示例用户。
- 示例用户晓林开启专项运动模块。
- 示例数据下，首页身体准备度不能空白。
- 演示中支持更改时间。
- 提供一张界面图，给从没见过的用户看，标题是「把手表里的各项数据，变成今天该怎么做」，并写明可以设定目标、验证习惯。
